## 任务拆分原则

- **最小增量**：每步只新增当前必须的代码，不提前引入后续功能
- **独立可验证**：每步完成后打开 index.html 就能看到该步功能跑起来
- **骨架稳定**：Task 1 建立的 HTML 结构 + CONFIG 常量 + 状态机框架，后续步骤只往上面加，不推翻重写

## 任务清单

### Task 1 — HTML 骨架 + CSS 变量 + CONFIG 常量定义

**目标**：搭建最小可运行骨架，页面能打开，无报错

- `js/main.js`：文件开头写 `const CONFIG = { ... }` 对象，把 spec 附录里的所有常量抄进来；空状态对象 `const state = {}`；空 `init()` 函数

**明确不做**
- ❌ 不写分数栏
- ❌ 不写开始按钮
- ❌ 不写小球
- ❌ 不写任何事件监听

**验收标准**（在浏览器验证）
- [ ] 页面打开显示浅黄色背景 `#FFF8E1`
- [ ] DevTools Console 无报错
- [ ] Elements 面板能看到 `<div id="game">`
- [ ] Sources 面板能看到 CONFIG 常量已加载

### Task 2 — 分数栏 + 开始按钮（静态 UI）

**目标**：页面有完整静态 UI，能看到顶部分数栏和居中按钮，但还没绑定任何逻辑

**新增内容**

- `css/style.css`：分数栏完整样式（position: fixed, top/left/width/z-index, 高度 64px）；开始按钮完整样式（居中、圆角、主色、hover 效果）；时间/得分字体样式
- `js/main.js`：新增 DOM 引用 `const $ = { scoreEl, timeEl, startBtn, container }`；`init()` 里做一次 DOM 查询

**明确不做**
- ❌ 不绑定按钮点击
- ❌ 不绑定倒计时
- ❌ 小球还不存在

**验收标准**
- [ ] 顶部分数栏固定在页面顶部，不滚动，左中右布局正确
- [ ] 分数栏显示"⏱ 60"和"当前得分：0"初始值
- [ ] 蓝色"开始游戏"按钮居中显示，hover 有上浮效果
- [ ] 按钮 hover 色值变为 `#1B5AA0`（Task 1 定义的 CSS 变量）
- [ ] 分数栏 z-index 正确（即使后续加球也不会被遮挡）

### Task 3 — 状态机 + 开场倒计时 + 游戏时间倒计时

**目标**：按钮能被点击，能走完整状态流：点击 → 5 秒倒计时动画 → GO! → 60 秒时间开始走

**新增内容**
- `js/main.js`：`state` 对象增加 `phase: 'idle' | 'countdown' | 'playing' | 'ended'`、`timeLeft`、`countdownNum`
- 函数：`onStartClick()`、`startCountdownLoop()`、`startGameTimer()`、`updateScoreboardUI()`、`endGame()`
- 倒计时 DOM：屏幕中央覆盖层，`countdownNum` 每 1000ms 从 5 递减到 1，最后显示 "GO!"，全部带下落弹跳 CSS 动画
- 游戏时间：GO! 后启动 `setInterval` 每 1000ms 让 `timeLeft--` 并更新 UI，归零调 `endGame()`
- ESC 键：倒计时阶段按 ESC 取消回到 idle；游戏进行中按 ESC 不处理

**明确不做**
- ❌ 不生成小球
- ❌ 不实现点击得分/扣分
- ❌ 结束画面只改分数栏状态，不弹遮罩层（留到 Task 6）

**验收标准**
- [ ] 初始 idle：按钮显示"开始游戏"
- [ ] 点击按钮：按钮隐藏，中央数字 5→4→3→2→1→GO! 逐个弹跳出现消失
- [ ] 倒计时中按 ESC：取消，按钮回归
- [ ] GO! 消失后分数栏时间每秒递减 1，从 60 走到 1
- [ ] 倒计时归零后 Console 打印"游戏结束"日志（占位，遮罩留到 Task 6）
- [ ] 最后 10 秒时间数字变红抖动 ✅ 同步做（难度不高，提前做减少返工）

---

### Task 4 — 小球生成 + 随机边界 + 间距检测

**目标**：游戏进行中页面会随机位置出现蓝色小球，同屏不超过 3 个，不重叠

**新增内容**
- `js/main.js`：函数 `generateBall()`、`computeSafeBounds()`、`getRandomPosition()`、`isOverlapping()`；新增状态 `state.ballsCount`
- CSS：`.ball` 类样式（60px 直径、蓝色 `#2E86DE`、内发光外阴影、border-radius: 50%）；小球出现动画（scale 0→1 + 下落 10px）
- 触发时机：`generateBall()` 在 GO! 消失后立刻调用 1 次；后续每生成/点中会在 Task 5 接

**明确不做**
- ❌ 不绑定小球点击事件
- ❌ 不做小球消失动画
- ❌ 同屏数量限制：先用一个 `max-on-screen` 简单 if 检测

**验收标准**
- [ ] GO! 消失后，游戏区域内出现 1 个蓝色圆形小球
- [ ] 小球不会贴页面边缘（四周至少留 20px）
- [ ] 小球不会出现在分数栏区域下方（safe bounds 正确）
- [ ] 连续生成 3 个时任意两球中心距离 ≥ 60px，无重叠
- [ ] 小球有从 scale 0 到 1 的淡入动画
- [ ] 同屏最多 3 个，达到后不再生成

---

### Task 5 — 点击交互 + 得分扣分 + 飘字反馈 + 小球消失 + 立即生成新球

**目标**：主玩法完整闭环。玩家点击小球得分，点空白扣分，有视觉反馈

**新增内容**
- 事件委托：在 `#game` 容器上绑 `click`
  - `event.target.classList.contains('ball')` → 点中分支
  - 其他 → 空白分支
- 点中分支：`state.score++`、小球放大 1.3× 消失动画（250ms）、移除 DOM、`generateBall()`、"+1" 绿色飘字 600ms 向上消失
- 空白分支：`state.score = Math.max(0, score - 1)`、分数栏数字红闪 200ms、"-1" 红色飘字 500ms 下坠消失
- 防重复得分：每个小球被点后立即 `element.style.pointerEvents = 'none'` 再开消失动画

**明确不做**
- ❌ 结束遮罩和再来一次（Task 6）

**验收标准**
- [ ] 点中小球 → 分数 +1，小球放大消失，+1 绿色飘字上飘，新球立即出现
- [ ] 点空白 → 分数 -1（最低 0），分数数字红闪，-1 红色飘字下坠
- [ ] 小球不会被重复点击得分（点中后快速连点同一球不会再加）
- [ ] 新球生成后同屏数量仍 ≤ 3

---

### Task 6 — 结束遮罩 + 再来一次按钮 + 重置逻辑

**目标**：60 秒归零后有完整结束体验，点再来一次能从头开始

**新增内容**
- `js/main.js`：`endGame()` 实现完整遮罩层（不再只是 Console 打印）；`resetGame()` 函数
- CSS：结束遮罩样式（全屏半透明黑 flex 居中）、遮罩内"游戏结束"标题 + 得分 + "再来一次"按钮
- `endGame()` 逻辑：停止定时器、清除所有小球 DOM、淡出剩余小球、显示遮罩、按钮文字改为"再来一次"
- 再来一次 → 重置所有 state → 回到 idle → 自动走开场倒计时（或回到手动点开始，暂定自动走倒计时更爽快）
- Esc 关闭遮罩 → 等同点再来一次

**明确不做**
- ❌ 历史最高分（用户没要）

**验收标准**
- [ ] 60 秒归零后遮罩层自动弹出，显示得分
- [ ] 遮罩出现时剩余小球同时淡出
- [ ] 点"再来一次" → 遮罩消失 → 分数归零 → 5 秒倒计时重新开始 → 60 秒计时
- [ ] 遮罩打开时按 Esc → 同效果重置

---

### Task 7 — 响应式断点 + 边界场景处理

**目标**：在不同屏幕尺寸和异常场景下游戏仍正常运行

**新增内容**
- CSS 媒体查询：768px / 480px 两档，小球尺寸 50px / 44px，倒计时字号缩放
- `visibilitychange` 监听：页面隐藏时暂停定时器，恢复时按剩余时间继续
- resize 处理：`computeSafeBounds()` 每次生成小球实时计算（已有，无需额外代码，只验证）

**明确不做**
- ❌ 不改核心玩法逻辑

**验收标准**
- [ ] Chrome DevTools 设 375px 手机宽度 → 小球缩至 44px，按钮缩至 140×44，不贴边
- [ ] 游戏进行中切换到其他标签页 30 秒再切回 → 倒计时从剩余时间继续（不是跳到 0）
- [ ] 无新 Console 报错
